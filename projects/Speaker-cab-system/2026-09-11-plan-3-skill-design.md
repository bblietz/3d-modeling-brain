# Plan 3 skill design (Unit 3 addendum)

Addendum to Unit 3 of [[2026-09-08-speaker-cab-system-design]]. Everything in the spec's Unit 3 that this document does not override still holds, and the Unit 2 addendum [[2026-09-10-plan-2-generator-design]] governs the generator. Plan 3 is written from this document in the Plan 2 format ([[plan-2-generator]]) and consumes the open items in [[speaker-cab-plan-1]], [[speaker-cab-plan-2]], and the ledger.

**Goal.** Run one MaximoCabs order end to end with Brian as the operator: from a pasted quote email or an interview to a committed order directory holding the brief, the approved voicing, the CAD package, the check table, and the customer proposal, with two stops for Brian, and after the build the listening-notes retrospective. Judgment lives in the skill prose and the knowledge notes; every number in a deliverable is written by code.

## 1. What changes against the spec's Unit 3

| Spec said | Now |
|---|---|
| `skills/speaker-cab/SKILL.md` alone | `SKILL.md` plus `templates/` (brief, proposal, listening notes) |
| The skill assembles the check table | `scripts/cabreport.py` writes `checks.md` from `voicing.json` and `cab.json`; operator rows are judged in place |
| The skill writes `proposal.md` from `cab.json` | `cabreport.py` fills the template's facts; Claude fills marked prose slots; a verify pass proves every fact survived |

## 2. Decisions from the brainstorm (2026-09-11)

- **Port loop**: when a port-fit blocker names the longest tube that fits, the skill re-runs the engine once with that tube pinned. If the re-run warns (clamped length or air speed) or blocks, the skill stops with the trade-off, front slot listed first, then raising Fb, then a larger box. The decision is recorded in Decisions locked.
- **Minimum port length**: `MIN_PORT_LENGTH_MM` rises from 20 to 24, the back panel plus the flange ring, so the planed-ring case cannot occur.
- **Port mouth**: a layout check warns when a port's inner mouth has less than one effective port diameter of free air along its axis; it never blocks.
- **Split**: one report module plus prose. Intake, tone target, ranking, approvals, the loop, the proposal prose, and the retrospective are prose; the check table and the proposal's facts are code.
- Groups one to three of the design (architecture and phases, contracts and touches, fixtures and process) were approved as presented; they are the sections below.

## 3. Modules and contracts

### 3.1 `skills/speaker-cab/SKILL.md`

Frontmatter `name: speaker-cab` and a one-sentence description in the furniture style: "Use when the user asks to design, voice, quote, or build a guitar speaker cabinet (guitar cab, 1x12, 2x12, extension cab, voicing a cab, a MaximoCabs order). For other furniture or woodworking use the furniture skill; for 3D-printable parts use the 3d-model skill." Section order follows the furniture skill: Backend choice, Prerequisites, Phase 1 Intake, Phase 2 Voicing, Phase 3 Plan, Phase 4 Build loop, Phase 5 Check table, Phase 6 Export and proposal, Phase 7 Handoff, Phase 8 After the build, Error handling. Headings use plain hyphens as the furniture skill does. Every command is written out with the absolute venv interpreter and runs from the vault root. The exit-code table (0 written or pass, 1 input error with nothing written, 2 blockers with files written; argparse usage errors also 2) appears once under Prerequisites, which also name the MaximoCabs repo at `~/ClaudeProjects/MaximoCabs` as the swatch source (optional; the no-swatch path covers its absence). The port loop of section 5 appears verbatim in Phase 4. The skill names two delegations under the vault's agent policy: the catalog read for ranking and the render inspection may go to subagents, with only conclusions returning to the brief.

Backend choice: build123d through `scripts/cabmodel.py`, always. There is no FreeCAD path for a cabinet; a CAD-layer failure that repeats identically is a defect in `cabmodel.py` or `cablayout.py`, fixed in the landed file and the mirror together, with a test. The skill says so in one line.

### 3.2 `skills/speaker-cab/templates/`

- `listening-notes.md`: the retrospective template: amp and settings, guitar, pedals in use, volume level, room; low end, mids, top, breakup onset, dispersion; the customer's words; Brian's words; prediction held (agree, partly, disagree) with a one-line reason; corrected construction defaults to promote; site-form gaps.

### 3.3 `scripts/cabreport.py`

Invoked from the vault root: `.venv/bin/python scripts/cabreport.py <order-dir> [--customer NAME] [--proposal-template PATH] [--verify]`. Reads `<order-dir>/voicing.json` and `<order-dir>/cab.json` and nothing else; the customer's name is in neither file, so `--customer` supplies it and is required whenever `proposal.md` is to be written (exit 1 without it). Imports only the standard library and `cabvoice` (for the air-speed limit and the prediction status constant). The template path defaults to `skills/speaker-cab/templates/proposal.md` under the vault root, found from the module's own location. Exit 0 written, 1 input error with nothing written (missing or unreadable file, missing key), 2 verify failed with every missing fact and empty slot listed.

- `checks.md` is written on every run: one table with columns Check, Value, Verdict, rows in this order. First the layout and CAD verdicts from `cab.json` in their own order, one row each, verdict and message verbatim. Then the engine rows from `voicing.json`: `power` (status and message), `wiring` (recommended option name, impedance, jack text; pass when the tap matches, warn otherwise), `port air speed` (value against the engine's limit; pass or warn; "n/a" for a box without a port), `alignment` (character with F3 or the cancellation frequency; info), and one `engine warning` row per entry in `warnings` (warn). Then the operator rows, each with its Value filled from the files and its Verdict set to the word `operator`: `stock thickness` (line and the shell, baffle, and back thicknesses from the parts), `grain and show face` (species on hardwood; "n/a, tolex line" as pass on tolex), `joinery fit` (corner joint and baffle mount), `stock yield` (blank count, total blank area, and sheets at 100 percent without nesting against 2440 x 1220 ply or 3050 x 600 hardwood glue-ups), `wood movement` (species or "n/a"; the climate comes from the brief), `transport` (external size in inches and mass in lb), `weight vs limit` (mass in kg and lb; the limit comes from the brief), `size vs limit` (external in mm and inches; the limits come from the brief). Claude replaces every `operator` with a verdict line; the file is final when none remains.
- `proposal.md` is written only when it does not exist, so a drafted proposal is never overwritten; to regenerate after a re-run the skill deletes it first. Facts come from the flag and the two files: the customer from `--customer`, the line from `cab.json` `line`, the configuration and back type from `enclosure`, the speaker label from `voicing.json` `speakers` (brand and model, with a count prefix for two drivers), the wiring from `wiring.recommended.jack_text`, the external size from `external_in` and `external_mm` as W x H x D, the mass from `mass.total_kg` and its pound conversion, the finish and grill cloth from the `aesthetics` block and `species`, the hardware summary from the `aesthetics` block (corners, handle, piping, feet) and the `hardware` list (jack plate), the swatch paths from the name table below, the lead time from a per-line table copied from the site (tolex "8 to 12 weeks from confirmed order", hardwood "10 to 14 weeks from confirmed order"), and the status line from `prediction_status`. Predicted frequencies never enter the proposal.
- Swatch table: the site's four tolex colors, four grill cloths, and four wood species mapped to their files under the MaximoCabs repo's `public/materials/` tree, emitted as `images/<file>` paths. An unknown name yields the line "no swatch on file" and a warning on stderr; the run still succeeds. Copying the files into the order's `images/` is a skill step; the module never reads the other repo.
- `--verify` reads the existing `proposal.md`, checks that every fact string is present and every slot holds text, and exits 2 with the list of failures otherwise.

## 4. Phases and stops

1. **Intake.** From a pasted quote email or an interview. The email's fixed layout (Cabinet, Finish, Grill, Speaker, Hardware, then Amps, Style, Venue, Notes) maps onto the Rig block; every template field stays present even when empty. Load-bearing follow-ups go out in one batch, and the skill stops for them only when there are any; everything else is a stated assumption.
2. **Voicing.** The tone target with one reason line per field, written to the brief and to `tone.json` (`min_power_w` is 1.5 times the highest rated amp, computed by the skill). Ranking against the catalog with the canonical keys and the precedence of section 7, three candidates with points, matched keys, and reasons. Back type with its reason. A standard-size order (the site box and no size limit) runs `evaluate` on the site box first and accepts it when the predicted character maps to the target's low end per the voicing note's bridge; otherwise, or when a limit or a pinned width applies, it runs `propose`. The engine command is recorded verbatim in the brief. The plain-language reading of the sheet goes in the brief. **Stop one:** Brian approves the voicing; the approval is a dated line in Decisions locked. No CAD before it.
3. **Plan.** Parts, joinery per connection, grain and show faces on hardwood, hardware positions, port location, and the aesthetics block written into `cab.py`. Presented briefly; no stop.
4. **Build loop.** Run `cab.py` plain for the layout verdicts, then with `EXPORT=1` for the CAD verdicts, the package, and the five renders, each viewed as a PNG. The port loop of section 5 applies. Any other blocker (impossible box, power stop, width floor over a limit) stops with the trade-off from the blocker text, and the choice is recorded.
5. **Check table.** `cabreport.py` writes `checks.md`; Claude judges the operator rows against the brief. Every row ends with a verdict line.
6. **Export and proposal.** The package is on disk from step 4. `cabreport.py` fills the proposal's facts, Claude writes the four prose slots in the site's voice, the swatches are copied into `images/`, and `--verify` passes.
7. **Handoff.** The brief's Artifacts and Decisions locked sections updated, the handoff file written, explicit-path commit and push. **Stop two:** Brian reviews `checks.md`, the renders, and the proposal, and fills the price line.
8. **After the build.** Retrospective in `knowledge/learnings/cab-<customer>-<config>.md` from the listening-notes template; the notes appended, dated, to the speaker's Field notes; corrected defaults promoted into [[speaker-cab-construction]]; memory updated when a rule changes.

## 5. The port loop

1. After the plain `cab.py` run, if `port fit` is a blocker, take the tube the blocker names (the layout names the longest tube or the shelf that fits).
2. Re-run the same engine command with `--port-tube <named>` added, then `cab.py` again.
3. If the second run has no blocker and no port warning, continue to the CAD run.
4. Otherwise stop and present, in this order: the front slot (`--port-slot` with the construction note's default slot), accepting the pinned tube's clamped tuning as reported, raising Fb with the larger tube (`--port-tube` and `--fb`), and a larger box (relax `--max-external` or the pinned width). Brian picks; the skill runs that command, records the trade-off and the choice in the brief, and continues.
5. When the blocker names only a shelf (no tube fits), step 2 is skipped and the stop offers the slot and the larger box.

## 6. Engine and layout touches

- `--port-tube MM` on `propose` and `evaluate`: one of `PORT_TUBE_ID_MM`, else exit 1. `size_port` neither grows nor snaps a pinned tube; the length is solved for that area. A length under `MIN_PORT_LENGTH_MM` is clamped with a warning stating the achieved tuning against the target; air speed over the limit becomes a warning instead of an enlargement. The sheet's `port` block gains `pinned: true` (false otherwise). On `evaluate` the flag is a validated `--port-diameter`.
- `--fb HZ` on `propose`: replaces the target tuning; the sheet records `port.fb_override_hz`. No other rule; the alignment character is computed from the result as today.
- `--port-count N` on `propose` and `evaluate`: the engine's existing per-chamber port count; 1 or 2.
- `MIN_PORT_LENGTH_MM = 24.0`; the clamp warning text follows; tests that pin 20 move.
- Width over the limit: where `propose` raises for a pinned width or the driver-count floor above the `--max-external` width, it now completes the sheet at the floor width with a blocker naming both numbers and the cause (pinned width or 2x12 floor) and exits 2, so the skill presents the trade-off (relax the limit, change the configuration).
- `port mouth` check in `cablayout.check_layout`, after `port fit`: for each port air entry, the free distance along the port axis from the inner mouth to the first solid whose projection overlaps the mouth's cross-section (basket and magnet envelopes, brace, divider, stiffeners, the baffle's back face for a rear port, the back panel's inner face for a slot). Warn when the distance is under one effective diameter (round: the tube ID; slot: the diameter of a circle with the slot's area); pass otherwise. The message names the distance, the obstruction, and the diameter. Check order becomes: sheet, net volume, stereo balance, cutout, grill opening, port fit, port mouth, magnet to back, handle, head match, line, jack plate, stock, part count, spans, then the CAD layer's interference, air volume, solid count, rectangularity (19). The CAD test's check-name mirror follows.
- `layout_report` adds an `aesthetics` block to `cab.json` with `corner_joint`, `baffle_mount`, `handle`, `corners`, `piping`, `feet`, `tolex_roll_in`, `tolex_color`, `grill_cloth`, `head_width_mm`, the `Aesthetics` dataclass as a dict. The existing top-level `corner_joint` and `baffle_mount` stay.

## 15. Amendments during plan writing (2026-09-11, evening)

Found while the plan's code and note text were developed and tested in the mirror and reviewed there; each is a deliberate deviation from the sections above and governs where they differ.

- **The port loop reads five blocker texts.** The layout's `port fit` blocker names the longest table tube that fits at the 24 mm minimum (or says no table tube fits), names the longest tube that fits at the same diameter when only the length is the problem, names the deepest shelf that fits for a front slot (or says none does), and reports slots wider than a rescaled chamber. The skill's loop gives one automatic re-run to the named tube (section 5 step 2), one to the next tube down the table when only the length is too long (a smaller area needs a shorter port at the same tuning), and one to the new chamber width when a slot outgrows its chamber; every other text goes straight to the trade-off stop. Section 5 step 1's "the tube the blocker names" is the first of these.
- **`--verify` writes nothing** and requires `--customer` (the customer's name is a verified fact). Every run without `--verify` rewrites `checks.md`, so the operator rows are judged after the last such run and again after a proposal is regenerated. Section 3.3's "written on every run" reads "every run without `--verify`".
- **`alignment` shows Fb and F3** on a ported box (F3 alone on a closed one, the cancellation frequency on an open one), since Fb is what the loop's decisions turn on; the proposal still carries no predicted frequency.
- **The proposal template puts the configuration on its own line** (`- Cabinet: Tolex 1x12, closed-back, ported` then `- Configuration: 1x12`).
- **The height floor over the size limit is a blocker** on the written sheet like the width floor (section 6 bullet 5 named the width only).
- **`port_dims`'s remedy sentence corrected**: a too-short port is lengthened by a larger port, a lower Fb, or a smaller box (length is proportional to area).
- **`port mouth` warns on the site default itself** (its 101.5 mm rear tube's mouth sits 84 mm behind the magnet with 18 percent of the mouth facing it), on every 1x12 front slot whose bottom panel needs a stiffener (Plan 2 starts it at the shelf's rear edge, so it reads as a 0 mm obstruction covering about 8 percent), and on slots in shallow boxes (the floor-level back cleat). Section 9's expectation that the site default passes is withdrawn; the construction note records the three cases with their per-order remedies; coverage is reported for information and does not gate the warn.
- **The catalog's Best with section is three bullets**: `Amp families` (unchanged text), `Genres` (keys only), and a third line keeping each note's qualifier sentences and the wikilink, so nothing was dropped (section 7 said two lines).
- **The calibration table moves one row** with the 24 mm minimum: Eminence Red White and Blues, proposed Fb 74 to 73 Hz, its clamped port now 24 mm.
- **The bridge is strict on ported boxes** (flat serves tight, punchy serves balanced, boomy serves big only), and the site box reads punchy with every catalog speaker, so a tight target always proposes; both dry-run fixtures are therefore tone-driven boxes, not the site box. A tolerance is Brian's call.
- **`SKILL.md` is 381 lines**, above the furniture skill's length, carrying the two full command blocks, the five-form loop, the exit table, and the operator-row table.
