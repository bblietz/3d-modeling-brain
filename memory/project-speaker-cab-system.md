Accent stripes landed 2026-09-15 against the ElShaieb order (customer's own quote-wizard notes had floated "alternate woods for striping e.g. purpleheart or maple" as a nice-to-have; Brian gave the exact geometry later - 1 in center stripe, two 0.25 in stripes each 0.75 in off the center stripe's own edge, wrapping all the way around). `Aesthetics.accent_stripes` is hardwood-line only: `((offset_mm, width_mm, species), ...)` measured across the panel's depth from its center, validated for known species and no overlap, the same pattern on all four shell panels since they share one depth. `cablayout.stripe_layout()` computes the (y0, y1, material, density) segments; `cablayout.blank_mass_kg()` approximates a striped panel's mass by each segment's share of the depth (documented as an approximation in its own docstring, not the exact CAD figure). `cabmodel.strip_part_entries()` cuts each segment as its own solid off the finished, joint-cut, roundover-clipped shell solid, so a striped shell panel becomes several named solids (`<panel>_stripN`) instead of one - `build()`'s air-subtraction loop and `check_build()`'s solid-count check were both updated for that (a blank can now emit more than one solid). A stripe crossing a finger or dovetail joint shows both species in that finger by design (the joint is cut into the lamination after glue-up), not a defect. **How to apply:** any future order wanting accent stripes just needs the `Aesthetics.accent_stripes` tuple in its `cab.py`; the capability, its tests, and its knowledge-note section (speaker-cab-construction.md, "Accent stripes") already exist. The client 3D preview (build_share.py/viewer.html) shows the real per-species geometry with a "with accent stripe / without stripe" selector (matching the Viewpoint selector's own look, a button pair, not a single toggle - Brian, 2026-09-15) so the customer can compare with and without the stripe - no second mesh export, since the selector just swaps each accent mesh's material between its own species texture and the shell's base texture (they tile seamlessly either way, from a shared per-panel UV seed). Building or changing this selector requires re-reading the exact CSP script hash from a real browser (`npx wrangler pages dev dist` locally), same as any other viewer.html module-script change. Verifying the 3D view itself needs a real browser with GPU/WebGL - this vault's own chrome-devtools sandbox cannot create a WebGL context (a standing environment limitation, confirmed harmless and unrelated to page correctness), so Brian should give a striped order's preview a look on his own machine before sending it.

Extended 2026-09-16: an order can now offer more than one accent-stripe design to compare (Brian: "add another striping option. make sure to keep all versions available in the website."), not just with/without a single design. Each extra design is a full sibling comparison build (its own `cab.py` with a different `accent_stripes` tuple, own `cab.json`/`cab.step`/cutlist/renders, sharing the order's `voicing.json`) alongside the canonical order, the same treatment `original/` already got for "no stripe" - see `projects/Cab-ElShaieb-1x12-hardwood/cherry-maple-stripe/` (0.75 in cherry centered, flanked with no gap by a 1.5 in maple stripe on each side). A genuinely different stripe pattern needs its own cut geometry (different boundary positions), so one mesh export can no longer represent every design by recoloring alone; `build_share.py` gained `--stripe-option "Label=none|primary|PATH"` (repeatable, order preserved) where a path tessellates that other order's own shell parts only (`is_shell_part()` filter) as a second geometry set, and `viewer.html`'s selector is now built from `CAB.stripeOptions`, showing or hiding whole geometry groups instead of just swapping materials. **How to apply:** to offer N designs on one order's preview, build each as its own sibling directory first, then pass one `--stripe-option` per design (plus `none` for plain, if wanted) to `build_share.py` in display order; omitting the flag entirely keeps the original with/without-stripe pair (or no selector) unchanged for every other order. This also surfaced and fixed a real bug: `cablayout.py`'s `Aesthetics.validate()` overlap check and `stripe_layout()`'s gap-fill check both used a bare comparison instead of the file's usual 1e-6 mm epsilon, so two stripes meant to touch with zero gap (valid, unlike the first design's real 0.75 in gaps) could misread as overlapping or grow a femtometre sliver of base material from ordinary binary-float noise in inch-derived offsets - fixed with regression tests using the real numbers that triggered it. Also 2026-09-16: the "take off the grill" toggle removed from the share-viewer entirely (Brian: "remove the option to take off the grill in the website ui") - the grill is now always shown, its previous default state. This is a shared-template (`viewer.html`) change, so it applies to any future order's preview, not just one; Cab-Blietz-1x12-hardwood's own preview is a separate, older claude.ai Artifact (never migrated to this site-hosted approach) and was deliberately left untouched, since republishing a live customer-facing Artifact is a distinct action from editing template code - ask Brian before touching it.
