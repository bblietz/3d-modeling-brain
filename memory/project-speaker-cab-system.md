Brian is adding a guitar speaker cabinet design capability to the vault for his MaximoCabs custom cab business (site repo at ~/ClaudeProjects/MaximoCabs, quote-only Astro site). Spec approved 2026-09-09 at projects/Speaker-cab-system/2026-09-08-speaker-cab-system-design.md, amended for Unit 2 by 2026-09-10-plan-2-generator-design.md and for Unit 3 by 2026-09-11-plan-3-skill-design.md. Locked: 1x12 and 2x12 (mono or stereo), closed, closed-ported and open-back; Thiele-Small voicing in scripts/cabvoice.py; finger joints on both lines with a through-dovetail option on hardwood; ears-only validation; builder package plus customer proposal; no pricing, no site configurator; judgment in prose, numbers in code.

Plan 1 done 2026-09-09 (engine, notes, twenty speaker notes). Plan 2 done 2026-09-11 (layout kernel, CAD layer, site-default fixture). Plan 3 done 2026-09-11: skills/speaker-cab/ (SKILL.md plus brief, proposal, and listening-notes templates), scripts/cabreport.py (checks.md and the proposal's facts from voicing.json and cab.json), engine flags --port-tube, --fb, --port-count, --accept-impedance-mismatch with size-limit blockers and a 24 mm port minimum, the layout's port mouth warn and port fit naming the tube that fits, canonical genre keys in the voicing note and every catalog note, and two fixture orders (projects/Speaker-cab-system/fixtures/sample-roots-1x12/ and rex-roots-1x12/) produced by dry runs of the skill. Retrospectives at knowledge/learnings/speaker-cab-plan-1.md, -plan-2.md, -plan-3.md.

Quote wizard done 2026-09-13 in the MaximoCabs repo (spec and plan in its docs/superpowers/, dated 2026-09-12). It is a multi-step, server-rendered intake under /quote/* on a Cloudflare worker, with KV drafts, Turnstile, and a Resend email laid out as the Rig block. The skill's Phase 1 reads that email (vault d43a494). It was merged with --no-ff into MaximoCabs main as 40ba39d and went live on 2026-09-13 (Pages deployment 3977b291) after QUOTE_DRAFTS was bound for Production; the live curl checks and Brian's browser walk with a real send passed. Wrangler 4.131.1 with CI on Node 22 (817774e) shipped as its own deploy the same day (0dc699b7). The first real quote, Cecilia Blietz's walnut 1x12, ran through /speaker-cab the same day (projects/Cab-Blietz-1x12-hardwood/, at stop two); along the way Brian ruled that hardwood grain wraps around the box, never front to back, and that hardwood shells get no glued stiffeners ([[feedback-hardwood-grain-wraps]]), and the report's swatch table was brought up to the site's photos. The account stays on Workers Free for now. Retrospective, locked decisions, and follow-ups: [[speaker-cab-quote-wizard]]. Two more generator-default fixes landed against this order on 2026-09-14: `render_stl.py`'s shading (vertex-normal shading plus matching-color edge strokes, since flat per-face shading and matplotlib's missing z-buffer banded the roundover fillet into stripes on any near-edge-on panel) and `GRILL_CLEARANCE_MM` 2 -> 4 mm (Brian, from experience: the old value left no room for the grill cloth to wrap the frame's edge), which also corrected `SHELL_MARGIN_MM` to 48 mm (its own comment's formula had been wrong, masked by a coincidence at the old 2 mm clearance; the mirror's 1200-case matrix test caught it). A third: "book-matched" was dropped everywhere the generator claimed it (`HARDWOOD_GRAIN_NOTE`, `cabreport.py`'s grain-and-show-face row, the construction knowledge doc, `SKILL.md`) since it was never buildable on this design at all, not a style choice — the shell corners are finger-jointed on end grain, and book-matching needs a long-grain seam (Brian, 2026-09-14).

**Why:** the site promises rig-specific volume, port, and baffle design; Plans 1 and 2 give it the acoustics and the geometry, Plan 3 the operator workflow with two stops for Brian (voicing approval, package review), and the quote wizard collects the rig answers the skill needs without follow-up emails.

**How to apply:** for any cab order, use the /speaker-cab skill from the quote email (Brian pastes it in; no Gmail/inbox connector exists yet to fetch it directly, and designing automated quote retrieval is deferred, 2026-09-15); the two fixture orders are the golden examples of a finished order and the port loop. Plan documents live in projects/Speaker-cab-system/; the Plan 3 mirror in its pipeline/plan3-mirror/ is the oracle the plan's code came from, and a fix to landed code is copied there and re-embedded. Every construction number is a starting value until a build measures it; confirm with Brian before trusting one. A push to MaximoCabs main deploys, and Cloudflare bindings live in the Pages project settings, so read them back through the Pages project API before any push that depends on one. Every order sent to a customer gets a 3D model preview page (Brian, 2026-09-15; the export's PNG renders are for the builder, not the customer). This is now hosted on the live MaximoCabs site, not a claude.ai Artifact (that was the first order's approach, since superseded): run `.venv/bin/python projects/Speaker-cab-system/pipeline/share-viewer/build_share.py projects/Cab-<...>` after the proposal is filled, copy `share/index.html` into `~/ClaudeProjects/MaximoCabs/public/share/<order-slug>/index.html`, commit and push that repo (deploys via GitHub Actions; confirm the run succeeds with `gh run list`/`gh run view` before calling it ready - a CI test failure here once meant a followup fix commit). The URL is `https://maximocabs.pages.dev/share/<order-slug>/`, unlisted (no nav or sitemap link, `public/robots.txt` disallows `/share/`, `X-Robots-Tag: noindex, nofollow`); Brian shares the direct link himself. Full procedure: [[speaker-cab-quote-wizard]] and `skills/speaker-cab/SKILL.md` Phase 6 step 4. The page's three.js CDN origin and two fixed script hashes live in MaximoCabs' `public/_headers` *and* its `src/lib/security-headers.ts` (a CI test enforces the two stay identical, since the worker-rendered `/quote/*` pages never see `public/_headers`) - touch both together if `viewer.html`'s two static inline scripts ever change.
