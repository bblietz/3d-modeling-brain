# Learnings: Clawd mascot

The 4-up plate printed successfully (2026-07-30) and the eyes fit flush against the re-cut sockets, validating the conformance-cut approach end to end. The findings below come from regenerating the mascot 3MFs and surgically fixing the 4-up plate's eye-socket gap. Project state: the brief in projects/Clawd-mascot.

## Bambu Studio 3MF gotchas

- **model_settings.config part matrices self-multiply on every GUI save** and cannot be trusted for geometry: the eye scale was stored as 1.00642624^4 = 1.0259538 after four saves (which is where the wrong "1.026x" note came from), and the body translation was stored at 5x its true value. The component transforms in the 3D model XML are the geometry-authoritative values; Bambu's loader ignores the metadata matrices (proved by round-trip: component transforms survive bit-exact while metadata matrices keep growing).
- Slicer part edits can include translation the user never intended: a perceived "scale the eyes" was actually +0.64 percent scale plus a 2.47 mm drag. When diagnosing fit problems in a GUI-edited 3MF, decompose the component transforms first; do not take the user's or the metadata's description at face value.
- Bambu duplicates mesh resources per object copy (one object file per copy) and stores meshes re-centered at their bounding-box center; account for that offset when swapping meshes.
- Embedded plate thumbnails are not regenerated by CLI round-trips; they show the stale arrangement until the next GUI save (cosmetic only).
- **`Metadata/layer_config_ranges.xml` keys objects by 1-based sequential model-object index, not the 3dmodel resource id.** A range authored with the resource id is silently dropped on load (no error, file just missing from the round-trip output). Per-object setting overrides in `model_settings.config` use plain `<metadata key=...>` lines on the object and round trip fine without touching `different_settings_to_system`.
- **Height ranges support ONLY `layer_height`; any other opt_key segfaults the slicer.** `sparse_infill_density` in a range loaded fine, survived CLI round trips and GUI saves, then crashed BOTH the GUI and CLI (02.08.01.55) at "Slicing mesh". Corollary: **a CLI round trip does not validate sliceability** - test-slice authored 3MFs with `bambu-studio --slice 1 --export-3mf` (exit 0) and confirm effects via `used_g` in the output's `slice_info.config`. For region-scoped settings use a `modifier_part` (box mesh + per-part metadata, e.g. `sparse_infill_density` 100%), which is the GUI-native mechanism and slices correctly. Note: a 100%-density region is still labeled and colored "Sparse infill" in the preview and gcode, so a solid ballast zone can be mistaken for runaway whole-model infill; confirm by extrusion-per-height-band from the gcode, not by preview color.

## Surgical fix pattern (mating-part conformance)

To fix a mating part that a slicer edit moved/scaled: restore the unsocketed base solid (fuse the original pocket back in), transform the mating solids by the exact affine from the 3MF component transforms, cut, then swap ONLY the affected mesh resources inside the zip. When folding such a fix back into a parametric FreeCAD document, replace the affected parametric features (here Part::Fillet) with baked Part::Feature objects rather than assigning .Shape: a later recompute of a live feature regenerates the OLD geometry and silently undoes the fix. Verify with: residual intersection volume 0, distToShape 0 with real contact area at the seat, entry-level zip diff (everything else byte-identical), and a bambu-studio round-trip preserving objects, extruders, colors, process, and bed type.

## Wide-eye kit iteration (2026-07-31)

Status: first print attempt showed the bodies printing hollow - lightning 5% infill only scaffolds top surfaces, so it is the wrong pattern for parts that need bulk strength or weight; treat lightning as a top-surface-support pattern, not structural infill. Eyes DID print before the run was cancelled and fit results are pending assembly. The kit was revised 2026-07-31: bodies get per-object grid 20% plus a "Bottom ballast solid third" modifier part (z 0-8.13 of 24.4 mm at 100% density, +45.6 g across 3 bodies, CLI-slice verified) after the first attempt at bottom-heaviness (a height range carrying `sparse_infill_density`) segfaulted the slicer - see the gotchas above. The user also added purple name texts and re-synced filaments to the AMS (bodies now orange). The fixed kit passed the GUI check, sliced without crashing, and the 3-body reprint started 2026-07-31; record fit and finish results here once printed and assembled.

### Decisions locked (print-validated or hard-learned; do not re-litigate)

- build123d is the default `/3d-model` backend; FreeCAD MCP is the escalation path. See [[build123d-trial]].
- Smooth tops default on both slicing routes: GUI preset "0.18mm Balanced Ironing @BBL X2D 0.6 nozzle" and `scripts/flatten_presets.py` + `scripts/apply_smooth_top.py`. The patcher must write the values AND the `different_settings_to_system` diff list, because the GUI silently resets keys missing from that list.
- Mascot eyes are separate press-fit parts at a measured zero-fit basis (parametrics in `projects/Clawd-mascot/eye_fit.py`). Never co-printed, never clearance-guessed. CAVEAT learned 2026-08-04: the calibrated number is FILAMENT-BRAND-SPECIFIC - the coupon-validated +0.02 mm interference printed smash-tight after a manufacturer change; the flush redesign ships -0.04 mm (one 0.06 coupon step looser, unvalidated) with the coupon ladder re-centered to -0.04/0.02/0.08 as fallback.
- Single-plate grouped kits are preferred over authored multi-plate structures: a hand-authored multi-plate 3MF passed the CLI round trip yet rendered EMPTY in the GUI, so GUI verification is mandatory for any authored 3MF.
- Textured-PEI bottoms cannot be fixed in software; presentation faces go up.
